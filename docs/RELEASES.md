# Политика публикации

## Канал обновлений

- Рабочим каналом публикации является ветка `main`, устанавливаемая как
  пользовательский репозиторий HACS типа **Integration**.
- GitHub Releases и автоматические release-теги не используются.
- Каждый опубликованный коммит должен быть получен через pull request и
  защищён обязательной проверкой `validate`.

## Версии

- Версия интеграции хранится в
  `custom_components/nikas_dyson/manifest.json`.
- Версии интеграции, UI и шаблона доставки фиксируются в
  `custom_components/nikas_dyson/panel_manifest.json`.
- Текущие версии в `README.md`, manifest и panel manifest должны совпадать.
- Изменение поведения отражается в `CHANGELOG.md`; добавление служебной
  обвязки репозитория само по себе не требует повышения версии продукта.

## Проверка перед слиянием

Перед публикацией функционального изменения:

1. Python-регрессии, браузерные сценарии, HACS и Hassfest проходят успешно.
2. Итоговый `validate` подтверждает успех всех обязательных заданий.
3. Production-bundle воспроизводимо собирается из исходников и проходит
   `scripts/check_panel_contract.py`.
4. Версии, маршруты и контрольные суммы активной панели согласованы.
5. Изменение проверено в Home Assistant; если проверка на реальных устройствах
   не выполнена, это явно указано в описании pull request.
6. `CHANGELOG.md` обновлён для функционального изменения.

## Откат

Откат выполняется новым проверенным pull request к ранее принятому состоянию.
История `main`, существующие теги и опубликованные объекты не переписываются и
не удаляются ради отката.
